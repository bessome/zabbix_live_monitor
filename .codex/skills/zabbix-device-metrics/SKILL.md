# Показатели устройств

Этот проект часто показывает одно значение двумя способами: текущее значение в карточке и историю в модальном графике. Перед изменением установи точное имя или ключ item в Zabbix, тип устройства, единицы, источник текущего значения и ожидаемый интервал обновления. Если фактическая структура item неизвестна, проверь доступные данные или явно обозначь допущение.

- Ищи определения item и выбор каналов в `zabbix_service.py` и `snmp_monitor.py`. Для модемов учитывай отдельные имена одноканальных и многоканальных моделей. Связывай ErrorRate с SNR только при однозначном совпадении канала и, если есть, частоты. Не показывай метрику другого канала из-за похожего имени.
- Для прямого SNMP используй существующие выбор OID, обработку поддерживаемых шагов preprocessing, community по типу устройства и общий кэш опроса в `snmp_monitor.py`. Проверь, не должен ли показатель читаться из Zabbix вместо SNMP. При таймауте текущее значение должно стать `n/a`, а не оставаться прежним.
- Маршруты карточек и API находятся в `routes_devices.py`. Сохраняй проверку пользователя, категории, видимости хоста и принадлежности item выбранному хосту. Историю бери из Zabbix через существующий `numeric_history` и периоды `HISTORY_PERIODS`; текущее SNMP-значение не подменяет историю.
- Интерфейс карточки находится в `templates/device.html` и соответствующих файлах `static/`. Сохраняй компактную мобильную компоновку, обе темы и понятное состояние без данных. Используй реальные единицы item; если появляются новые шкалы графика, подпиши их.
- Проверяй затронутые случаи в `tests/test_snmp.py` и `tests/test_app.py`: разные имена item, отсутствие item, неоднозначное сопоставление каналов, таймаут или ошибка, если изменена обработка опроса. Запускай подходящие тесты через интерпретатор PyCharm. Общие правила проекта находятся в `AGENTS.md`.
